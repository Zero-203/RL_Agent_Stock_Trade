> 版本：v1（第 1 周基础联调交接版，公共接入口已完成自测）。接口变更须更新本文件版本号并同步受影响角色。
>
> 依据：[小组项目计划 v2.0](小组项目计划v2.0.md)、[P1 训练模板说明](../scripts/README_train_model.md)、[SSE48 数据说明](README_sse48_baostock_v2.md)。P2 回测侧约定见 [P1 与 P2 回测交接契约](P1_P2_回测交接契约_v1.md)。
>
> 适用范围：P3 接入 PPO/RecurrentPPO 与简单门限，P4 接入 SAC/TQC 与 Critic 门限，P5 消费无门限候选与验证结果。

## 1. 算法注册

训练侧统一识别的算法名：`ppo`、`ddpg`、`td3`、`sac`（现有基线），以及 `recurrentppo`、`tqc`（新增，依赖 `sb3-contrib==2.7.1`）。

- 新增算法由 P1 提供公共接入口；算法行为正确性、特殊超参数与门限规则由 P3（RecurrentPPO、简单门限）与 P4（TQC、Critic 门限）在第 2 周确定、验证并冻结。
- 依赖或构建未通过时，接入口返回明确错误，不回退到 PPO 或 SAC，不使用占位结果通过验收。
- FinRL 原始 MODELS 表中的 A2C 保留，不纳入 v2.0 必做实验。

## 2. 训练接口

入口：

```powershell
python scripts/train_template.py --config <JSON> --dataset <NAME> --algorithm <ALGO> --seed <INT> [--timesteps N --run-type smoke|pilot] [--device auto|cpu|cuda]
```

- `--run-type`：`smoke`、`pilot`、`main` 三类隔离；覆盖 `--timesteps` 时必须为 smoke 或 pilot；覆盖不改变 rollout/batch 等参数。
- 配置校验按当次 `--algorithm` 检查对应配置段；不要求一份 JSON 同时包含全部算法配置，P3、P4 可分别交付。
- 参数透传：`training.policy` 为默认策略；算法配置段中的 `policy` 可覆盖之，`policy_kwargs` 与算法参数原样传给 SB3 构造。P1 不预设、不冻结学习率、网络结构、种子、步数和门限值。
- 策略约束：`recurrentppo` 使用 sb3-contrib 循环策略（如 `MlpLstmPolicy`）；不得用单一全局策略覆盖全部算法。
- 预算语义：PPO/RecurrentPPO 的实际步数按 rollout 上取整，运行清单记录请求步数与实际步数；off-policy 记录实际梯度更新数。

## 3. 预测接口与循环状态

- 模型加载分类：on-policy（`ppo`、`recurrentppo`）不传入 `buffer_size`；off-policy（`ddpg`、`td3`、`sac`、`tqc`）推理加载使用 `buffer_size=1`。不得以 `algorithm == "ppo"` 判断加载方式。
- 循环状态契约（RecurrentPPO）：预测输入为观测、LSTM 隐藏状态和 episode start 标记；输出为动作和下一步隐藏状态。调用形式：`model.predict(obs, state=states, episode_start=starts, deterministic=True)`。
- 新回合、独立验证、独立测试必须从初始隐藏状态（`None`）和 `episode_start=True` 开始，不跨数据集泄漏状态。
- 真实 RecurrentPPO 状态行为由 P3 在第 2 周验证，并核对训练验证与回测两条路径的轨迹一致性。

## 4. 模型产物与元数据

- 模型保存为 SB3 原生 `.zip`，位于 `trained_models/<DATASET>/<algorithm>/`，同名不覆盖。
- zip 内 `metadata.txt`（说明行 + JSON）及同目录 `effective_config.json` 记录：算法、数据集、种子、`requested_timesteps` 与 `actual_timesteps`、off-policy 的 `actual_gradient_updates`、配置策略与 `actual_policy`、算法参数、环境参数、数据路径与训练/验证哈希、`train_start`/`train_end`/`validation_start`/`validation_end`、有序股票与指标名单、观察/动作维度、价格口径与环境源码 SHA256；`runtime` 记录 Python、平台、Git 修订与依赖版本（含 `sb3-contrib`、`stable-baselines3`、`torch`）。
- 运行清单 `results/train_model/<DATASET>/<run_id>/run_manifest.json` 关联模型、日志、验证账户曲线与动作轨迹；失败运行记录错误类型与信息，状态标记 failed。
- 训练运行产物自动记录训练/验证 CSV 的 `data_hashes` 与共享环境的 `environment_code_sha256`；全量数据集指纹冻结口径以 P2 发布的数据清单为准。

## 5. 门限调用接口（仅推理）

- 推理顺序固定为：模型原始动作 → 可选门限 → 动作校验 → `env.step`。
- 条件标识：每次运行记录算法、门限类型（无门限/简单门限/Critic 门限）、门限参数与实现标识。门限未实现时明确报不可用（`NotImplementedError`），不得把无门限结果标记为有门限结果。
- 动作规格：单环境动作是与 `ordered_tickers` 对齐的 `float32` 向量，形状 `(48,)`，取值 `[-1, 1]`；VecEnv 边界可为 `(1, 48)`，调用门限前移除批维、返回后恢复。拒绝非有限数、维度或范围错误，不静默截断或重排。
- 简单门限（P3）：逐资产过滤，被拒绝资产动作置零，其余保持。
- Critic 门限（P4）：可拒绝整条动作向量；拒绝时输出全零向量并记录 `accepted=false`。Critic 的输入坐标与价值比较规则由 P4 在第 2 周登记，未登记不运行 Critic 门限。
- 资金、持仓、停牌与风险强平约束由共享环境最终执行，门限不替代环境检查；风险强平优先级高于门限放行。

## 6. P5 选优输入

- P1 提供：无门限候选模型 zip、运行清单、验证期账户曲线与动作轨迹、失败状态、模型与数据版本标识。
- 统一 Sharpe 等指标口径沿用 P2 的回测指标契约；P1 不在训练模板中另设指标，也不执行最终选优。
- P5 按 v2.0 第 3.5 节在验证集固定选优；联调阶段不读取测试绩效。
