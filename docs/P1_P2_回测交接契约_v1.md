> 依据：[小组项目计划 v2.0](小组项目计划v2.0.md)、[P2 统一回测框架](README_backtest.md)、[SSE48 数据说明](README_sse48_baostock_v2.md)。面向 P3–P5 的训练与门限约定见 [P1 接口契约 v1](P1_接口契约_v1.md)。

## 1. P1 交付物（回测侧消费）

| 交付物 | 位置 | 说明 |
| --- | --- | --- |
| 模型 | `trained_models/<DATASET>/<algorithm>/<stem>.zip` | SB3 原生 zip，内含 `metadata.txt` |
| 运行清单 | `results/train_model/<DATASET>/<run_id>/run_manifest.json` | 状态、产物路径、运行时信息 |
| 验证产物 | 同目录 `validation_account_value.csv`、`validation_actions.csv` | 训练端验证预测结果 |
| 有效配置 | 同目录 `effective_config.json` | 与 zip 内 metadata 一致 |

## 2. 模型识别与加载

- 算法集合：`ppo`、`ddpg`、`td3`、`sac`、`recurrentppo`、`tqc`。`recurrentppo` 由 sb3-contrib `RecurrentPPO` 加载，`tqc` 由 sb3-contrib `TQC` 加载。
- 加载分类：on-policy（`ppo`、`recurrentppo`）不传 `buffer_size`；off-policy（`ddpg`、`td3`、`sac`、`tqc`）加载传 `buffer_size=1`。
- 加载后校验：模型观察/动作空间与回测环境一致；股票身份与顺序一致（同维度不同股票也拒绝）。
- 元数据读取：zip 内 `metadata.txt`（标题行 + 空行 + JSON），JSON 的 `effective_config` 为有效配置（已新增 `requested_timesteps`、`actual_timesteps`、`actual_policy`、off-policy `actual_gradient_updates` 及 `data_contract.train_start`；`runtime.packages` 新增 `sb3-contrib`）；旧模型缺字段时按现有规则回退校验原训练 CSV。

## 3. 循环状态回放契约（RecurrentPPO）

- 回放循环内调用 `model.predict(obs, state=states, episode_start=starts, deterministic=True)`，保留返回的下一步隐藏状态。
- 回合开始或独立回放开始时 `states=None`、`starts=True`；跨验证/测试数据集不得复用隐藏状态。
- 回放日期、账户价值、动作与训练端验证预测应在预冻结容差内对齐（现有基线：逐字节/数值容差 rtol 1e-12、atol 1e-9）。

## 4. 门限调用位置与日志

- 推理顺序：模型原始动作 → 可选门限 → 动作校验（维度/范围/有限性）→ `env.step`。
- 门限条件字段：`threshold_mode`（`none`/`simple`/`critic`）、门限参数、`accepted`（Critic）、逐资产拒绝标记（simple）。
- 日志区分三个量：模型原始动作、门限后动作、环境请求（门限后动作 × `hmax` 向零取整的复权模拟单位）与实际成交。实际成交与请求不一致时按现有 `reason` 分类（`not_tradable`、`risk_liquidation`、`cash_position_or_environment_limit`、`hold_or_integer_rounding`、`filled`）。
- 门限未实现时回测入口明确报不可用，不把无门限结果标记为有门限结果。

## 5. 数据与环境一致性

- 数据契约以 P2 发布的冻结版本与 [数据说明](README_sse48_baostock_v2.md) 为准；训练元数据记录数据版本标识。
- 回测沿用现有校验：训练/验证/测试日期不重叠且测试晚于验证；验证模式只接受训练记录中的验证数据；测试数据不得以改名方式复用训练/验证数据。
- 环境一致性沿用现有环境源码标识机制；环境源码变化时按既有契约处理，不绕过校验静默回放旧模型。
- 注意：训练端验证预测与回测回放应使用同一环境配置（含 `tradability_policy`）；不一致时拒绝回放并记录。

## 6. 接口状态明细（已有接口、待确定项、需修改项）

### 6.1 已有接口（已落地并完成合成数据自测）

- **训练产物与元数据（P1）**：`src/train_model/runner.py` 已输出 SB3 `.zip`（内含 `metadata.txt`）、`effective_config.json`、`run_manifest.json` 及验证集曲线/动作；新增 `requested_timesteps`、`actual_timesteps`、`actual_policy`、off-policy `actual_gradient_updates`、`data_contract.train_start` 与 `runtime.packages["sb3-contrib"]`，保留原 `data_hashes` 与 `environment_code_sha256` 兼容。
- **元数据与算法校验（`src/backtest/data.py`）**：`read_metadata` 已支持识别 `ppo`、`ddpg`、`td3`、`sac`、`recurrentppo`、`tqc`；股票名单顺序、日期边界与环境哈希校验沿用原逻辑。
- **模型加载分类（`src/backtest/runner.py`）**：`run_backtest` 已映射 `RecurrentPPO`、`TQC`，按 `algorithm in ("ppo", "recurrentppo")` 区分 on-policy（不传 `buffer_size`）与 off-policy（传 `buffer_size=1`），并在 `run_manifest.json` 记录 `inference_replay_buffer_size`、`threshold_mode` 与 `sb3-contrib` 版本。
- **循环状态回放与门限钩子（`src/backtest/runner.py`）**：`replay` 已支持 `RecurrentPPO` 的 `state` / `episode_start` 连续传递与回合重置；提供 `apply_threshold(raw_action, threshold_mode, threshold_config, critic=None)` 入口（`None`/`"none"` 原样透传并校验一维有限范围，其他模式明确抛 `NotImplementedError`）；`actions.csv` 已包含 `model_action`、`thresholded_action`、`threshold_mode`、`requested_shares`、`executed_shares`、`adjusted_execution_price`、`reason`。
- **现有 CLI 与汇总入口（`scripts/backtest.py`）**：`check-data`、`run`、`batch`、`summarize` 四子命令可正常运行无门限四算法回放，23 项单元测试与 `scripts/smoke_backtest.py` 均已通过。

### 6.2 待确定项（需 P2 确认或第 2 周与 P3/P4 共同冻结）

1. **门限条件标识与文件命名**：有门限回测时输出目录的命名格式（当前为 `{algorithm}_s{seed}_{split}_{uuid}`，是否加入 `threshold_mode` 及候选标识），以及 `run_manifest.json` 中门限参数、门限实现哈希的字段名。
2. **门限附加诊断日志字段**：`actions.csv` 是否在 `thresholded_action`、`threshold_mode` 基础上固定增加 `threshold_accepted`（布尔值，区分 Critic 整向量拒绝或简单门限逐资产拒绝）及 Critic 估值摘要列，抑或单独输出门限诊断表。
3. **门限实现与 Critic 注入签名**：第 2 周对接 P3（简单门限）与 P4（Critic 门限）时，门限模块的函数签名，以及 `replay` 向 `apply_threshold` 传入当前观测 `obs`、已加载 `model`/`model.critic` 和环境参数 `hmax` 的具体约定。
4. **重复运行与配对汇总规则**：同一无门限模型在 `none`、`simple`、`critic` 三条件下配对回测时，`summarize_runs` 的分组键与去重键设计。

### 6.3 需修改项（P2 回测侧调整清单）

1. **`scripts/backtest.py` 与 `run_backtest` 参数扩展**：`run` 子命令与 `batch` 任务配置当前未暴露 `--threshold-mode`、`--threshold-config`；`run_backtest` 目前仅从模型训练 `effective_config` 读取 `threshold_mode`（训练阶段恒为无门限），需改为支持回测调用时显式传入推理门限模式与参数并覆盖默认值，写入回测 `run_manifest.json`。
2. **`summarize_runs` 多条件聚合支持（`src/backtest/runner.py`）**：当前 `summarize_runs` 按 `["algorithm", "seed"]` 判重并仅按 `algorithm` 聚合；后续同一种子模型需回测无门限/简单门限/Critic 门限三个条件，需将 `threshold_mode`（及冻结条件标识）纳入记录列、判重键与分组统计键，同时继续拦截同条件下的重复混入。
3. **`replay` 门限上下文透传（`src/backtest/runner.py`）**：当前调用 `apply_threshold(raw_action, threshold_mode, threshold_config)` 未传入 `obs` 与 `model`（Critic 门限计算价值所需），需扩展调用入参并在门限返回后再次校验动作形状 `(n,)`、有限性与 `[-1, 1]` 范围。
4. **回测文档同步（`docs/README_backtest.md`）**：随 P2 上述调整同步更新 CLI 参数表、`actions.csv` 字段说明与汇总规则。

## 7. 联调安排

1. **第 1 周基础联调（本周完成）**：基于现有无门限模板与合成/候选数据，P1 提供 `ppo`、`sac`、`recurrentppo`、`tqc` 公共接入口生成的 smoke 模型与验证产物；P2 核对第 6 节接口状态，完成无门限模型加载、LSTM 状态回放、训练端验证曲线与 P2 回放对齐，以及现金/持仓/费用/reward/停牌/风险强平对账，确认或完成第 6.2、6.3 节回测侧接口调整。
2. **第 2 周算法与门限联调**：P3/P4 接入各自正式策略配置与门限实现后，与 P1/P2 联合验证真实策略状态行为及 `none`/`simple`/`critic` 条件日志、拒绝行为与配对汇总；`test` 集在正式冻结前仅做结构校验，不读取绩效用于任何选择。

## 8. 已知边界

- 本契约不要求 P2 实现门限算法本身；门限规则由 P3/P4 提供。
- 测试绩效不用于确定候选、阈值或选中模型。
- 云端运行另行验证，不以本地联调结果替代。
